# 视觉理解层策划书

> 状态：核心能力已实现并验证 · 2026-08-21
> 代码位置：`src/desktop_pilot/vision/window_detector.py`
> 工具入口：`desktop_detect_windows` / `desktop_detect_ui_elements`

## 一、目标

让 AI **通过截图自主理解图形界面**——不依赖 UIA 控件树（自绘界面读不到、结构不稳定），
纯靠图像分析 + OCR 实现"看到界面 → 认出元素 → 决定操作"。

用户需求演进：
1. ~~窗口级检测~~ ✅ 已实现（识别屏幕上所有窗口矩形）
2. ~~元素级检测~~ ✅ 已实现（17 种 UI 元素类型分类）
3. 待做：功能推理（AI 判断"这个元素点了会发生什么"）
4. 待做：模板学习（熟悉界面秒识别）

## 二、架构

```
┌────────────────────────────────────────────────┐
│  Agent (Hermes)                                │
│    调用 desktop_detect_ui_elements             │
└───────────────┬────────────────────────────────┘
                ▼
┌────────────────────────────────────────────────┐
│  ToolRegistry (tools/registry.py)              │
│    _detect_ui_elements(window_id)              │
│    - 解析窗口 rect（跳过最小化）                 │
│    - 截全屏 → 裁切窗口区域                       │
│    - 调 vision 层                              │
└───────────────┬────────────────────────────────┘
                ▼
┌────────────────────────────────────────────────┐
│  Vision 层 (vision/window_detector.py)         │
│                                                │
│  第一层：窗口检测                                │
│    Canny 边缘 → 膨胀 → 轮廓 → boundingRect     │
│    输出: [{rect, area, center, color}]         │
│                                                │
│  第二层：元素检测（OCR 优先策略）                 │
│    ① 全图 OCR (pytesseract image_to_data)      │
│       - 中文单字合并 ("选"+"择"→"选择")          │
│       - 每个 OCR 词 = 一个候选元素               │
│    ② 轮廓检测补充无文字元素                      │
│       - 自适应阈值 → 轮廓 → 过滤与OCR重叠的      │
│    ③ 形状分类 (_classify_element)               │
│       - 有文字 → text_label/button/link        │
│       - 无文字 → checkbox/icon/image/...       │
└────────────────────────────────────────────────┘
```

## 三、17 种 UI 元素类型及判定规则

| 类型 | 判定依据 | 实测准确度 |
|---|---|---|
| button | 中文短语(2-6字)/英文按钮词 + 面积中等 | 高 |
| text_label | 有文字默认值；纯数字/符号 | 高 |
| link | 蓝色文字 (b>120, r<100) | 高 |
| input_field | （待改进：目前靠轮廓+宽高比） | 低 |
| checkbox | 正方形 <40px | 高 |
| icon | 极小正方形 / 中小面积 AR 1.4-2.5 | 中 |
| dropdown | 窄高 (AR<0.7) | 中 |
| toggle | 极扁 (AR>2, area<2000) | 中 |
| slider | 窄长条 (AR>5, h<20) | 高 |

| progressbar | 水平条 (3<AR<12, 15<h<40) | 中 |

| image | 大面积无文字 (>8000px²) | 高 |
| container | 特大面积 (>80000px²) | 中 |
| radio_button | （待实现，和 toggle 共用规则） | — |
| tab | （待实现） | — |

## 四、关键技术决策（踩坑记录）

1. **OCR 用全图扫描而非逐元素**
   - 逐元素 OCR：pytesseract 对小图需要上下文，识别率≈0
   - 全图扫描：`image_to_data` 返回每个词的位置+置信度，效果好
   - 文字匹配回元素框：中心点落在框内即归属

2. **中文单字合并只合 CJK**
   - 初版按水平距离合并 → 英文单词被粘连（"Spinxjoinedthegame"）
   - 改成只合中文单字（`'一'<=c<='鿿'`），英文保持空格分隔

3. **checkbox 严格化**
   - 初版 `area<3000 且正方形` → 大量假阳性（24个）
   - 改为 `<40px 正方形` → 降到 7 个真 checkbox

4. **最小化窗口必须跳过**
   - Windows 给最小化窗口的 rect 是 (-32000,-32000)
   - 不跳过会导致裁切出 0×0 区域 → OpenCV 崩溃或空结果

5. **tesseract 路径自动绑定**
   - 引擎装在 Program Files 但不在 PATH
   - `_ocr_full_region` 里自动调 `_tesseract_cmd()` 绑定

## 六、已知问题（优先级排序）

1. **input_field 检测几乎不工作** —— 需要检测边框特征（四边灰度突变）
2. **radio_button/tab 无独立规则** —— 和其他类型混在一起
3. **unknown 仍占 ~21%** —— 需要更多形状特征（圆角检测？颜色直方图？）
4. **重叠窗口无法分离** —— Canny 只找到最外层轮廓；需要 PrintWindow 单窗截图（已验证可行）
5. **速度 ~1-3s/窗口** —— 可用降采样优化
